# dsh-boss 嵌入式前端设计

> 本文为第一版设计，保留作宿主接口调研参考。产品结构与交互以[第二版个人求职工作台设计](product-frontend-design.md)为准：对话仍为主，右侧增加地图、直接编辑和 AI/MCP 共同维护记录。

版本：第一版设计稿 · 2026-10-26（Asia/Shanghai）

宿主基线：DeepSeek Harness `0.2.1-rc.2`

配套文档：[技术架构](technical-architecture.md)、[项目目标与范围](../README.md)

本稿确定界面分工、交互流程和客户端接入边界，供下一步实现。已核对本机安装版本的前端说明和相关接口，并核对官方固定版本资料。原型使用合成岗位、经历和状态，没有连接招聘平台、简历服务或真实 DSH 会话；其宿主外观是交互示意，未要求逐像素复刻。下文区分宿主已有能力与插件拟新增契约，不能把设计稿视为已完成集成。

## 1 设计结论

采用 **DSH 对话 + 会话右侧求职面板 + 原生 PDF 页签**。对话负责表达意图、模型解释和工具执行；右侧负责查看资料、比较修改和审阅。新增一个“我的求职”主导航入口，用来找回跨会话的任务；连接配置进入 DSH 设置。

用户始终只面对一套对话、一套输入框、一套模型设置和一套执行审批。插件不新增聊天窗口，也不嵌入完整 BOSS 或 Reactive Resume 网站。首个闭环仍是“城市搜索两页 → 完整 JD → 单岗位简历副本 → 中文 PDF 审阅”。沟通确认仅作为后续 M4 的交互预留。

| 界面位置 | 插件内容 | 与 DSH 的配合 |
| --- | --- | --- |
| 原有对话区 | 搜索结果摘要、简历版本卡片、真实动作结果 | 沿用宿主消息流、工具事件及展开查看能力 |
| 会话右侧面板 | 岗位详情、简历审阅、进展记录 | 注册一个求职页签类型，沿用宿主分栏、切换、收起与全屏 |
| 原生文件页签 | 已生成的具体版本 PDF | 通过授权文件引用打开，使用宿主文档预览 |
| “我的求职”主面板 | 任务列表、来源会话、恢复入口 | 使用主导航与主面板扩展，承载跨会话查询 |
| DSH 设置 | 连接状态、母版选择、搜索默认值 | 使用设置扩展；凭据存储和连接校验由宿主侧处理 |

## 2 页面结构与视觉约束

```text
DSH 原有左栏      DSH 原有对话                         DSH 会话右栏
────────────     ────────────────────────             ────────────────────────
会话 / 工作区    用户：杭州 Python 后端，先看两页      [求职] [简历预览.pdf]
我的求职        模型解释 + 搜索结果卡片               岗位标题、公司、城市
…               模型解释 + 简历版本卡片               [岗位详情 / 简历审阅 / 进展]
设置            原生输入框、模型选择、发送            当前页内容与相关操作
```

原型默认展示左栏收起后的窄轨状态，便于比较对话与右栏的比例；实际插件尊重用户现有布局。DSH 左栏默认宽度 280px、收起宽度 56px，右栏首次展开约占视口 45%，随后记忆用户尺寸；插件不另写一套拖拽或宽度持久化。[布局][layout]

样式以 DSH 的颜色、字体、间距、按钮和表单组件为准。插件只定义业务内容层的布局，保留宿主页签栏，不再叠加第二个应用顶栏。强调色仅用于当前选择和操作，状态同时提供文字。首版不展示未经校准的“匹配分数”；直接展示有依据的经验、缺失条件和待确认项。

## 3 三种交互必须分清

| 用户行为 | 前端行为 | 是否启动模型 / 外部动作 |
| --- | --- | --- |
| 点击岗位、切页、展开依据、预览 PDF | 切换当前视图；必要时向插件 Host 读取已有数据 | 不启动模型，不执行招聘平台写入 |
| 点击“加入定制请求” | 生成带明确任务引用的待发送请求，交给原输入框 | 用户发送后才进入 DSH turn |
| 点击“确认这版内容” | 保存具体版本的内容审阅记录 | 属于本地业务写入，不代表允许对外沟通 |
| 请求发起沟通 | 在活动 turn 中准备不可变动作计划，调用原生审批 | 宿主返回可信许可后才可执行 |

切换选中的岗位只是 UI 状态变化，模型不会自动知道。只有用户明确发送的请求或受控工具读取，才把所选任务加入模型上下文。不能偷偷改系统提示词，也不能把“打开了某岗位”解释成“同意为它投递”。

### 3.1 与原输入框协作

默认动作名称为“加入定制请求”，避免让用户误以为点完就开始生成。请求包含可读的公司、岗位和任务引用，用户可以补充语气、长度和重点，再使用 DSH 原有发送按钮。

当前 `SessionInput.setDraft(text)` 会替换整个草稿，并清除输入中的内联引用。因此，真实接入不能通过“读取纯文本 + 拼接 + setDraft”模拟无损追加。[对话输入契约][conversation]

- 输入确实为空时，经适配层设置草稿；提交前再次校验当前会话和草稿状态。
- 已有文本、附件或引用时，先在插件里保留待添加请求；只有验证过宿主的受控插入机制后，才支持原位追加。应使用宿主作用域和定位语义，不能直接修改编辑器 DOM。
- M1 若不能证明插入不丢引用、不覆盖并发输入，使用“显示请求供复制”的降级入口，保留原草稿，不强行自动填入。
- 活动 turn 尚未结束时沿用宿主排队、补充或停止语义，不能绕过它直接从浏览器启动第二条工作流。

原型使用普通文本框演示加入与发送两个步骤，不能证明 DSH 富文本输入的插入合同。`sendSession(...)` 是实际发送接口，不应用于“加入请求”这个按钮。

## 4 首次使用与连接设置

未配置时，“我的求职”展示一个明确的起点：连接岗位服务、连接简历服务、选择母版。只展示当前缺少的下一步，不在对话中反复输出完整设置说明。

| 状态 | 展示与操作 |
| --- | --- |
| 未配置 | 显示缺少的连接，跳到 DSH 对应设置区域 |
| 岗位登录失效 | 显示需重新登录；保留搜索进度和已保存 JD |
| 简历连接正常但没有母版 | 提供读取已有简历与选择母版入口；先核对导入结果 |
| 权限或版本不兼容 | 说明不可用能力，禁用对应操作，提供脱敏诊断 |
| 连接已就绪 | 显示账号可识别摘要、母版名称及最近检查时间 |

前端只读取脱敏连接状态和宿主配置投影，不接触 Cookie、MCP 凭据或签名下载地址。配置写入遵循宿主 revision 冲突机制；切换账号后重新解析归属，旧任务不自动继承新账号权限。

## 5 岗位发现与详情

搜索结果以工具卡片出现在对话中。卡片展示城市、关键词、已获取页数、去重后的数量和本批代表性岗位；较多结果在右侧或任务页展开。平台继续取下一页与本地列表翻页应使用不同文案，例如“继续获取下一页”和“查看已获取岗位”。

点击某一行，打开关联 session 的求职页签，参数包含 `taskId` 或 `searchRunId + jobSnapshotId`。搜索结果阶段可以尚未建立定制任务，不能提前编造 `taskId`。

右侧“岗位详情”展示：公司、岗位、城市、薪资、来源链接、抓取时间、是否完整 JD、职责与要求。对照区域逐条提供资料事实引用，明确区分“有依据”“不满足”和“待补充”。仅有列表摘要时显示“尚未获取完整 JD”，获取详情要作为可见的工具操作，不能把列表信息装成完整 JD。

选择岗位不会覆盖已有简历任务。用户请求定制时，Host 固化 JD 快照、资料版本和母版身份，再返回新的任务。内容刷新后旧快照仍可追溯。

## 6 简历审阅与 PDF

“简历审阅”先显示目标岗位、母版与副本版本、改动数量和未解决项，再按段落展示原文、新文、修改原因及事实依据。默认纵向对比，窄侧栏不强行左右并列；复杂内容使用宿主全屏审阅。对比组件只处理简历领域数据，不接管 DSH 的代码 diff 或通用文件浏览器。

没有依据的技能、年限和成果不进入正式文案。对待确认项可补充事实、排除该项或返回对话澄清。补充事实产生新资料版本，相关改写及审阅应重新计算，不能直接把“已审阅”复用到新内容。

“确认这版内容”绑定 `taskId + revision + profileVersionId + jobSnapshotId + resumeVersionId`。内容审阅和最终 PDF 核验分开记录：内容确认通过不代表中文字体、换行和分页合格。最终 `REVIEWED` 应同时满足内容检查与指定文件的实际核验，最终文件变化时重新核验。[技术架构状态机](technical-architecture.md#10-状态机与真实发送)

PDF 生成后以独立的 DSH 文件页签打开，保留任务、简历版本和产物关联。优先使用宿主提供的 `openFile` 回调或规范资源打开接口，文件由 Host 下载、验证和登记；浏览器不直接打开 Reactive Resume 的临时签名链接，也不通过 iframe 嵌入它的编辑网站。[文档预览][documentpreview]

**文件权限是 M1/M3 的验证项。** 架构中的产物位于 `DSH_HOME/dsh-boss`，不能假定宿主的工作区文件读取自动包含该目录。必须验证合法的会话文件引用、附件或产物导出通路；若不支持，则增加带授权检查的插件资源读取接口。不能用任意绝对路径、`file://` 或扩大工作区读取范围来凑预览。

原型中的 PDF 页签是排版示意，不是真实导出的文件。实际实现需提供加载、文件缺失、生成中、版本过期和渲染失败状态；预览失败不能删除已生成产物。

## 7 沟通确认与进展记录

首版 PDF 闭环之后才接 M4 沟通。用户在对话里明确发起动作，Host 生成计划，DSH 原生审批展示目标账号、公司与岗位、真实动作、正文语义及附件状态。插件可在审批前展示摘要，但不另建一个可以绕开宿主的“同意”按钮。

当前上游默认招呼能力不能发送任意自定义正文或指定 PDF。界面应直接写“向该岗位发起平台默认招呼”，附件栏写“本次不发送附件”。“发送文字”“发送 PDF”在适配验收前不启用；不能把“发起沟通”叫作“简历投递成功”。

原型中的确认框只示意信息层级。实际确认框的样式、许可范围、拒绝与活动 turn 生命周期由 DSH 决定，不要求复刻原型按钮外观。不得因用户之前勾选“内容已核对”就跳过原生审批。

“进展记录”按事实列出 JD 获取、简历副本、导出、内容审阅、文件核验、沟通、附件等事件。后端超时且可能产生外部效果时，显示“结果待核验”；只提供核验入口，不能显示一个会直接重发的“重试”。撤销许可、取消请求、执行失败、效果未知分别展示。

## 8 跨会话任务与历史卡片

右侧面板属于会话，当前会话不存在时不能依赖它展示业务。“我的求职”用独立主面板列出保存任务、来源会话、岗位、当前材料版本和最后业务状态。首版采用简单列表，不建设统计大屏或另一套工作区。

“继续审阅”先验证关联会话仍存在且有权访问，再通过宿主导航恢复会话并打开该任务页签。原会话已删除时仍可在全局任务页查看业务数据；如要继续模型工作，由用户明确选用或创建会话，后端更新关联，不能悄悄借用当前窗口中的另一会话。

历史工具卡片呈现调用完成时的不可变摘要；“查看当前任务”才拉取最新状态。比如历史卡片写 v2，后来已生成 v3，卡片仍写 v2，详情提示“另有新版本”。不能将历史事件悄悄替换为最新执行结果。

## 9 与 DSH 扩展点的映射

以下宿主符号已经从 `0.2.1-rc.2` 安装资料或固定版本资料核对；业务 ID 和组件名是本项目拟议命名。正式代码仍须以安装版本的类型检查和最小集成验证为准。

| 需求 | DSH 已有接口 / 扩展点 | 接入约束 |
| --- | --- | --- |
| “我的求职”导航 | `sidebar.panellist` 与 keyed `main` | 使用一致的插件 panel ID，如 `dsh-boss.overview`；不占用保留的 `conversation` |
| 主面板切换 | `ctx.layout.selectPanel(id)`、`beginNavigation()` | `null` 回到 Conversation；异步导航遵守取消信号 |
| 会话内轻入口 | `conversation.session.header.actions` | 可放一个“求职”入口；不替换整个标题或原生右栏开关 |
| 求职右栏页签 | `ctx.sidebarRightTabs.register(...)` | 注册 `id/kind/title` 等定义，生命周期由 `ctx.effect` 托管 |
| 页签内容 | `ctx.slots.register({ name: 'sidebar.right.pane.tab', key: definition.id }, Body)` | key 是定义的 `id`，不能误用 `kind` |
| 打开/读取页签 | `ctx.sidebarRight.openTab(kind, { params })`、`useTabInfo()` | 校验 `navigation.params`，使用所属 Session 与 tab 生命周期，不手拼内部地址 |
| 工具结果卡片 | keyed `tool.call.toolview` | 按真实领域工具 wire name 注册；独立 Client renderer |
| PDF | 宿主 `openFile` 或 `ctx.sidebarRight.openResource(...)` | 仅使用已经验证的授权资源引用，不自行构造文件权限 |
| 设置页面 | `settings.section` 与 `ctx.configForms.get(entryId)` | 读取 namespace snapshot，写入处理 revision 冲突，服务可用性跟随生命周期 |

工具 UI 通过 `ToolCallOwnerProps` 读取 `preparing/start/result`、调用 ID 和结构化结果。DSH Runtime 继续负责调用与结果配对、折叠和 PTC 嵌套展示。Host 的 `presentCall/presentResult` 不会自动变成浏览器 UI，不能只写 Host renderer 就声称已有前端卡片。[工具展示][tool]

客户端卡片消费带 `cardSchemaVersion` 的持久结果摘要；未知版本或缺失字段回落到通用结果视图，不能出现空白消息。摘要仅含渲染所需字段与授权对象 ID，不放完整私密资料或签名 URL。展开全部工具结果仍由宿主负责。

## 10 客户端结构、状态与契约

继续单个 TypeScript 插件包，新增客户端入口，使用宿主 React 与组件依赖，避免重复打包 React、Cordis 或 DSH 服务。拟议目录：

```text
src/client/
  index.ts                     注册导航、右侧页签、工具视图、设置
  host-adapter.ts              封装导航、输入、文件、主题与通知接入
  remote.ts                   访问插件 Host 服务，校验响应
  state/task-store.ts         按对象 ID 缓存快照与 revision
  panels/job-workspace.tsx    岗位 / 审阅 / 进展
  panels/overview.tsx         跨会话任务
  cards/search-result.tsx     搜索摘要
  cards/resume-result.tsx     简历与产物摘要
  components/resume-diff.tsx  修改与事实引用
  settings.tsx               设置区域
```

### 状态归属

| 状态 | 权威来源 | 客户端处理 |
| --- | --- | --- |
| 当前会话、活动 turn、草稿、右栏大小/页签、审批 | DSH | 读取并调用宿主公开接口，不自建副本竞争 |
| JD 快照、资料与简历版本、产物、审阅、动作记录 | 插件 Host / 数据库 | 带 revision 获取，变更后重新读取，后台恢复 |
| 当前查看子页、展开的事实、对比展示方式 | 当前页签客户端 | 可随页签恢复；不能当作业务成功或审批凭据 |

### 拟新增 Host 服务

以下是插件内部契约草案，**不是 DSH 已存在的 API**。所有参数与返回值进行 schema 校验；网络与数据库操作留在 Host。

| 拟议方法 | 关键输入 / 输出 | 用途 |
| --- | --- | --- |
| `connections.getStatus` | 脱敏连接状态、支持的 capability、检查时间 | UI 按实际可用能力展示 |
| `tasks.list` | 游标、范围 → 摘要与下一游标 | 跨会话列表；服务端过滤授权范围 |
| `tasks.get` | 任务 ID、上下文 → 快照、revision、材料引用 | 加载或恢复当前任务 |
| `tasks.watch` | 任务 ID、最后 revision → 业务更新或重新同步提示 | 活动页签订阅；传输机制按 DSH 服务能力落地 |
| `reviews.confirmContent` | 任务 ID、expectedRevision、版本集合 → 新 revision | 记录内容核对，不签发外部执行权限 |
| `artifacts.confirmReview` | artifact ID、哈希、expectedRevision → 文件核验记录 | 防止核验旧文件后替换新文件 |
| `requests.prepare` | 来源会话、任务/岗位引用、意图 → 可读请求与受控引用 | 构造待发送草稿，不在浏览器执行领域任务 |

服务端校验对象归属、会话权限及版本关系。浏览器传入 `sessionId` 不能自行赋予权限；跨会话全局页可以读取授权业务摘要，但不能拿另一会话的身份执行动作。真实搜索、改写、导出和沟通沿用架构中的领域工具与 DSH 执行管道。

异步响应必须同时匹配对象 ID、navigation revision 和请求序号。用户从岗位 A 切到 B 时，A 的迟到响应不能覆盖 B。页签关闭时释放订阅及未完成只读请求；折叠隐藏时按可见性暂停非必要刷新，不取消 Host 已接受的任务。任务完成不强行抢回用户焦点。

写入遇 revision 冲突时保留用户待提交内容，展示“内容已有更新”并要求重新核对。重连先重新拉取权威快照，禁止仅凭丢失的 UI toast 推断成功。乐观更新只用于展开、选择等界面状态；审阅、导出及外部动作均等待 Host 结果。

## 11 响应式、键盘与异常状态

- 桌面并排聊天与右栏，宽度和左栏联动遵循宿主。DSH 在空间不足时会缩减或关闭右栏；插件不抵抗该行为。
- DSH 在低于 768px 时将右栏打开为全屏，返回后继续原会话；不能在窄屏额外叠出另一套聊天。原型采用同样的单主视图策略，但其 430px 导航隐藏是演示压缩处理，正式导航仍由宿主管理。
- 审阅段落自然换行，操作按钮允许换行。PDF 放大使用原生文件预览；正文不为塞进侧栏缩到不可读。
- 页签和按钮有可读名称，状态带文字，核对项使用原生复选框。错误区可聚焦到实际恢复入口；异步进度使用适量 live region，不逐 token 朗读。
- 进入任务详情时先显示加载状态；加载失败保留已有快照并标注过期。空结果、部分页失败、登录失效、JD 不完整、事实不足、版本冲突、文件缺失和效果未知分别处理。

## 12 实施拆分与验收

与技术架构使用同一组 M1–M5 编号，UI 不形成另一个独立交付计划。

| 阶段 | 前端交付 | 核心验证 |
| --- | --- | --- |
| M1 接入合同 | 设置与连接状态、最小页签、默认工具结果 | 安装卸载释放注册；导航会话正确；输入插入和文件授权验证 |
| M2 岗位闭环 | 搜索卡片、JD 面板、分页状态 | 两页与去重数量一致；选择不自动发送；切换不串数据 |
| M3 简历闭环 | 修改依据、内容确认、原生 PDF、任务恢复入口 | 同一资料两个 JD 独立版本；不覆盖母版；真实中文 PDF 与内容分别核验 |
| M4 受控沟通 | 计划摘要、原生审批、真实执行结果 | 取消不执行；版本变化使计划失效；未知效果不重发；沟通与附件分开 |
| M5 批量跟进 | 跨任务筛选、恢复、回复与面试记录 | 单项失败不阻塞其他任务；重启后状态一致 |

开发验收至少覆盖以下容易出错的路径：

1. 输入框已有文字与引用时加入请求，原内容、附件及引用均保留；发送前不启动 turn。
2. 加载 A 时切到 B，晚到响应不覆盖 B；在另一个会话打开任务也不串引用。
3. 页签折叠、关闭、全屏、切换主面板和刷新后，可以从持久任务恢复。
4. Host 任务继续运行时卸载 UI、断线或刷新，不重复执行外部写入。
5. 历史工具卡片保留历史版本；错误/未知 schema 有通用回退；普通调用与 PTC 子调用均正确显示。
6. 内容或文件更新后原核对状态失效；已确认内容与已核验 PDF 有独立记录。
7. 明暗主题、320px 窄屏、桌面并排和键盘操作可用，不出现遮挡或必须悬停才能使用的操作。
8. 登录失效、版本冲突、下载失败、审批拒绝和结果未知都有可执行的恢复路径。

**建议第一步实现：** 在测试 profile 中加载一个最小客户端插件，只验证“对话工具卡片 → 正确会话右侧页签 → 已授权 PDF 页签 → 回到原草稿”。这条链路成立后，再逐步接真实岗位、简历和审批数据。
